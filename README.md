### Проделанная работа

#### Спринт 1: Архитектура бэкенда (Рефакторинг)

Исходный код бэкенда представлял собой монолит, где в одном файле (`service.py`) смешивались HTTP-запросы, бизнес-логика, файловые операции
и SQL-запросы. Это нарушало принцип единственной ответственности (SRP) и делало код нетестируемым.

**Что было сделано:**

- **Внедрена слоистая архитектура (Layered Architecture):** Проект разбит на независимые слои: `api` (роутеры), `services` (бизнес-логика) и
  `repositories` (слой доступа к данным).
- **Паттерн Репозиторий:** Вся работа с SQLAlchemy (SQL-запросы, сессии) изолирована в `repositories/`. Сервисы больше ничего не знают о
  таблицах базы данных напрямую.
- **Dependency Injection (DI):** Связывание слоев реализовано через систему зависимостей FastAPI (`Depends`). Это позволяет легко подменять
  реальные репозитории на моки (mocks) при написании Unit-тестов.
- **Централизация конфигурации:** Захардкоженные `DB_URL` и пути к файловой системе вынесены в `core/config.py`, образуя единую точку
  управления настройками.
- Исправлена ошибка сборки Docker-образа фронтенда (удален ошибочный шаг копирования несуществующего файла `.env.production`).
